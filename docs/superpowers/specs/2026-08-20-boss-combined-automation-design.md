# BOSS 沟通列表与推荐牛人全流程自动化需求文档

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 需求名称 | BOSS 沟通列表与推荐牛人全流程自动化 |
| 需求版本 | V1.0 |
| 日期 | 2026-08-20 |
| 适用模块 | 本地招聘工作台 / BOSS 自动化 |
| 目标岗位 | 用户在“BOSS 自动化”页面选择的当前岗位 |

## 2. 背景与问题

当前“BOSS 自动化”页面提供以下两个独立入口：

1. 开始沟通列表自动化；
2. 开始推荐牛人自动化。

两个入口需要用户分别启动，且推荐牛人打招呼后，候选人会进入沟通列表。若系统
只把推荐牛人作为独立的末端流程，就不能及时处理这些候选人的回复，也容易继续
联系更多推荐候选人，导致已回复候选人长时间得不到处理。

本需求需要新增一个统一入口，由后台按照“沟通列表优先、推荐牛人补充候选人、
再回沟通列表处理回复”的顺序循环执行。两个来源不得并发操作 BOSS 页面。

## 3. 目标

1. 在现有自动化控制区新增“开始全流程自动化”按钮。
2. 自动锁定当前岗位，先同步并处理沟通列表。
3. 沟通列表没有立即待处理候选人时，才进入推荐牛人阶段。
4. 推荐牛人每联系 20 人后，必须回到沟通列表重新同步并优先处理回复。
5. 推荐牛人产生的新会话统一进入沟通列表后续流程。
6. 页面刷新或重新打开后，仍能显示后台全流程的真实运行状态。
7. 统一支持暂停、继续、停止、额度限制、时间限制和失败恢复。
8. 保留现有两个独立启动按钮及其既有行为，不造成回归。

## 4. 非目标

1. 不修改现有候选人硬筛、对话、专业问答、简历申请和附件终审规则。
2. 不提高现有每日额度，也不绕过 BOSS 平台限制。
3. 不允许沟通列表与推荐牛人同时操作 BOSS 页面。
4. 不因为新增统一入口而重复发送打招呼语、非专业问题、专业问题或简历申请。
5. 不将等待回复、等待附件的候选人错误视为当前必须阻塞的任务。
6. 不移除“开始沟通列表自动化”和“开始推荐牛人自动化”两个独立入口。

## 5. 用户界面需求

### 5.1 新增按钮

在“开始推荐牛人自动化”按钮后新增：

```text
开始全流程自动化
```

按钮顺序为：

```text
同步沟通列表
开始沟通列表自动化
开始推荐牛人自动化
开始全流程自动化
暂停
继续
停止
```

### 5.2 按钮可用状态

| 页面状态 | 开始全流程自动化 |
| --- | --- |
| 未选择岗位 | 禁用 |
| 正在同步沟通列表 | 禁用 |
| 独立自动化正在运行 | 禁用 |
| 全流程正在运行 | 禁用 |
| 全流程已暂停 | 禁用，使用“继续”恢复 |
| 全流程已停止、完成或失败 | 启用 |
| BOSS 未登录 | 可点击，但后台返回明确登录错误，不能显示为已启动 |

### 5.3 状态展示

自动化控制区必须持续展示以下信息：

1. 当前岗位；
2. 全流程总状态；
3. 当前执行阶段；
4. 当前推荐批次已联系人数，格式为 `x/20`；
5. 沟通列表本轮立即待处理人数；
6. 沟通列表和推荐牛人各自的当日已用额度及剩余额度；
7. 下一步动作；
8. 最后一次状态更新时间；
9. 停止、暂停或失败的具体原因。

阶段展示文案至少包括：

```text
准备启动
正在同步沟通列表
正在处理沟通列表回复
沟通列表当前无立即待处理候选人
正在读取推荐牛人
正在执行推荐牛人，第 x/20 人
推荐批次完成，正在返回沟通列表
已暂停
正在安全停止
今日额度已用完
已到执行结束时间
全部流程完成
执行失败
```

## 6. 核心业务定义

### 6.1 立即待处理候选人

满足以下任一条件的候选人属于“立即待处理”：

1. 有未读候选人回复；
2. 候选人最新消息版本相对本地已处理版本发生变化；
3. 候选人已经回复非专业问题，等待系统评估并进入下一阶段；
4. 候选人已经回复专业问题，等待系统评估、决定是否申请简历；
5. 候选人已经发送或同意分享简历，等待确认、下载或分析；
6. 候选人处于可自动重试状态，且重试时间已经到达。

以下状态不属于“立即待处理”，不得阻塞推荐牛人阶段：

1. 等待候选人回复；
2. 等待候选人发送附件；
3. 已完成终审；
4. 已明确淘汰或无需继续操作；
5. 需要人工复核；
6. 尚未到达自动重试时间。

### 6.2 当前候选人的当前步骤

“当前步骤”指系统已经开始且需要原子完成的一次候选人动作，例如：

1. 读取并校验当前候选人资料；
2. 读取并确认一组最新消息；
3. 对候选人最新回复完成一次评估；
4. 发送一条已经确认的回复；
5. 对一位推荐牛人完成硬筛并决定跳过或打招呼；
6. 确认一次简历分享并完成本次下载状态落库。

达到结束时间或收到停止请求后，允许完成已经开始的当前步骤，但不得开始下一位
候选人，也不得自动进入下一阶段。

### 6.3 推荐批次

1. 每个推荐批次最多成功联系 20 位候选人。
2. 明确硬筛不通过且未发送打招呼的候选人不计入“已联系人数”。
3. 已经联系过、重复出现或状态不允许再次联系的候选人不计入人数。
4. 推荐列表不足 20 位可联系候选人时，处理完当前可用候选人后立即结束本批次。
5. 每批结束后必须返回沟通列表，不允许连续开始下一批。

## 7. 全流程执行顺序

### 7.1 启动

用户点击“开始全流程自动化”后：

1. 校验已经选择当前岗位；
2. 校验 BOSS RPA 浏览器登录状态；
3. 校验没有其它独立自动化或全流程占用平台操作锁；
4. 锁定本次任务的岗位标识、岗位名称和启动时间；
5. 读取沟通列表与推荐牛人各自的时间窗口、每日额度和单次配置；
6. 创建全流程运行记录；
7. 自动同步当前岗位沟通列表；
8. 同步成功后进入沟通列表优先处理阶段。

启动后即使用户在页面切换岗位，本次任务仍使用启动时锁定的岗位。切换岗位只影响
下一次启动，不能让运行中的任务跨岗位处理候选人。

### 7.2 沟通列表优先阶段

1. 使用当前岗位重新读取沟通列表快照。
2. 根据未读标记、消息版本和本地候选人阶段生成立即待处理队列。
3. 按以下优先级执行：
   - 已发送或已同意分享简历，等待下载和分析；
   - 已回复专业问题，等待评估；
   - 已回复非专业问题，等待评估；
   - 其他有新回复或消息版本变化的候选人；
   - 到达重试时间的可重试候选人。
4. 每位候选人执行前必须重新校验 `friend_id` 与当前岗位。
5. 历史对话和本地状态决定下一动作，不得重复发送已完成阶段的问题。
6. 本轮没有立即待处理候选人后，才允许进入推荐牛人阶段。
7. 等待回复或等待附件不阻塞阶段切换。

### 7.3 推荐牛人阶段

1. 开始阶段前重新读取当前岗位推荐牛人列表。
2. 候选人继续使用现有硬筛规则。
3. 明确不符合的候选人直接跳过，不发送消息，不调用对话 AI。
4. 已经联系过或已经存在于当前岗位队列的候选人跳过，不能重复打招呼。
5. 符合或信息不足的候选人使用当前岗位已经配置的打招呼语。
6. 每成功联系一位候选人，推荐批次计数加一。
7. 成功联系达到 20 人、推荐列表耗尽、推荐额度耗尽或推荐时间窗口结束时，结束本批次。
8. 批次结束后进入“返回沟通列表”阶段。

### 7.4 返回沟通列表

1. 重新同步当前岗位沟通列表；
2. 推荐牛人产生的新会话与原有会话统一进入沟通列表；
3. 优先处理所有立即待处理候选人；
4. 沟通列表再次没有立即待处理候选人后，若推荐阶段仍允许执行，则开始下一批；
5. 若推荐阶段已经达到额度、时间或列表耗尽条件，则结束本次全流程。

### 7.5 主循环

```text
启动并锁定岗位
  -> 同步沟通列表
  -> 处理全部立即待处理候选人
  -> 沟通列表当前无立即任务
  -> 推荐牛人最多联系 20 人
  -> 返回并重新同步沟通列表
  -> 优先处理新增回复和简历动作
  -> 根据额度、时间和推荐池状态决定继续下一批或结束
```

## 8. 时间与额度规则

### 8.1 独立额度

1. 沟通列表使用沟通列表设置中的每日额度。
2. 推荐牛人使用推荐牛人设置中的每日额度。
3. 两个来源分别计数，互不占用额度。
4. 全流程入口不新增第三套额度，也不修改现有额度。
5. 某一来源额度耗尽时，该来源不得开始新的候选人步骤。

### 8.2 独立时间窗口

1. 沟通列表阶段遵循沟通列表设置中的执行时间窗口。
2. 推荐牛人阶段遵循推荐牛人设置中的执行时间窗口。
3. 未启用某来源的定时任务时，手动全流程不受该来源定时窗口限制，但仍受现有安全节奏和每日额度约束。
4. 已启用时间窗口的来源，在窗口外不得开始新的候选人步骤。
5. 沟通列表作为最高优先级来源，如果其窗口已结束，则全流程安全停止，不能继续推荐新人而无法处理回复。
6. 推荐牛人窗口已结束但沟通列表仍允许执行时，系统完成当前沟通列表检查后安全停止，不继续等待或空轮询。
7. 到达结束时间时，完成当前候选人的当前步骤后停止，不开始下一位候选人。

## 9. 候选人状态连续性

全流程必须复用现有候选人状态机和对话记录，不能为统一入口创建一套彼此冲突的
候选人阶段。

每次处理前至少判断：

1. 是否首次进入对话；
2. 是否已经发送非专业问题；
3. 候选人是否已经回复非专业问题；
4. 非专业回答是否已经评估；
5. 是否已经发送专业问题；
6. 候选人是否已经回复专业问题；
7. 专业回答是否已经评估；
8. 是否已经申请简历；
9. 是否已经收到在线简历或附件简历；
10. 简历是否已经下载、解析和分析；
11. 最新候选人消息版本是否已经处理；
12. 当前岗位和 `friend_id` 是否仍然一致。

同一候选人、同一岗位、同一消息版本只能执行一次状态推进。推荐牛人来源转入沟通
列表后继续使用同一个候选人记录，不能重新创建“首次对话”状态。

## 10. 暂停、继续与停止

### 10.1 暂停

1. 点击“暂停”后设置全流程暂停请求。
2. 当前已经开始的候选人步骤完成后进入暂停状态。
3. 暂停期间不得开始新候选人、切换阶段或发送消息。
4. 页面刷新后仍显示已暂停状态。

### 10.2 继续

1. 点击“继续”后从已持久化的阶段和批次计数恢复。
2. 恢复前重新校验登录、岗位、时间、额度和平台锁。
3. 若恢复条件不满足，保留暂停状态并显示具体原因。
4. 不得因继续操作而重置推荐批次计数或重复处理当前候选人。

### 10.3 停止

1. 点击“停止”后设置全流程停止请求。
2. 当前已经开始的候选人步骤完成后停止。
3. 停止后不得自动进入下一阶段或下一位候选人。
4. 记录停止阶段、已处理数量、批次计数和停止原因。
5. 再次点击“开始全流程自动化”创建新一轮任务，但复用既有候选人状态和去重信息。

## 11. 后台设计

### 11.1 全流程调度器

新增独立的全流程调度器，职责仅限于：

1. 串行编排沟通列表和推荐牛人来源；
2. 维护当前阶段与批次计数；
3. 检查时间、额度、暂停和停止条件；
4. 调用现有自动化协调器执行单个来源；
5. 等待来源达到本轮可切换状态；
6. 持久化和投影全流程状态。

全流程调度器不得复制候选人筛选、消息判断、对话生成、简历处理等业务逻辑。
这些能力继续由现有来源协调器和候选人状态机负责。

### 11.2 状态机

建议状态如下：

```text
idle
  -> preparing
  -> syncing_conversations
  -> processing_conversations
  -> loading_recommendations
  -> processing_recommendations
  -> returning_to_conversations
  -> completed

任一运行状态
  -> pausing -> paused
  -> stopping -> stopped
  -> failed
```

状态记录至少包含：

| 字段 | 说明 |
| --- | --- |
| `run_id` | 本轮全流程唯一标识 |
| `job_id` | 启动时锁定的岗位 |
| `state` | 总状态 |
| `phase` | 当前业务阶段 |
| `recommendation_batch_count` | 当前批次成功联系人数，范围 0-20 |
| `conversation_immediate_count` | 最近一次沟通列表立即待处理人数 |
| `conversation_processed` | 本轮沟通列表累计处理人数 |
| `recommendation_contacted` | 本轮推荐牛人累计成功联系人数 |
| `started_at` | 启动时间 |
| `updated_at` | 最后更新时间 |
| `next_action` | 下一步动作说明 |
| `stop_reason` | 完成、停止、时间或额度原因 |
| `error` | 结构化失败信息 |

### 11.3 平台操作锁

1. 全流程和两个独立自动化入口共用同一个平台操作锁。
2. 任一独立自动化运行时不得启动全流程。
3. 全流程运行时不得启动任一独立自动化。
4. 沟通列表和推荐牛人阶段只能串行执行。
5. 页面按钮状态只是交互提示，后台必须再次执行并发校验。

## 12. API 需求

建议新增以下接口：

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `POST` | `/api/recruiting/automation/full-flow/start` | 启动当前岗位全流程 |
| `POST` | `/api/recruiting/automation/full-flow/pause` | 请求暂停 |
| `POST` | `/api/recruiting/automation/full-flow/resume` | 继续已暂停任务 |
| `POST` | `/api/recruiting/automation/full-flow/stop` | 请求停止 |
| `GET` | `/api/recruiting/automation/full-flow` | 获取完整状态 |

启动参数只允许包含当前岗位标识。推荐批次大小固定为 20，不由页面临时传入，避免
前端状态与后台实际规则不一致。额度和时间配置从现有设置读取。

`/api/state` 需要增加全流程状态投影，供现有页面轮询恢复显示。

## 13. 异常与恢复

| 异常 | 处理方式 |
| --- | --- |
| BOSS 未登录或登录失效 | 当前步骤安全结束后失败，显示“BOSS 登录失效”，不得继续推荐 |
| 当前岗位不存在或映射失败 | 启动失败，不得回退到其它岗位 |
| 沟通列表首次同步失败 | 全流程失败，不进入推荐牛人 |
| 返回沟通列表同步失败 | 保留批次进度并失败，不继续下一批推荐牛人 |
| 推荐列表读取失败 | 保留沟通列表处理结果并失败，可人工继续 |
| 候选人身份校验失败 | 当前候选人失败或跳过，不能点击其他候选人代替 |
| 单个候选人处理失败 | 记录结构化原因；可安全跳过的错误继续本阶段，不安全错误停止全流程 |
| AI 输出无效 | 候选人转人工复核，不自动发送猜测内容 |
| 页面刷新或前端关闭 | 后台任务继续，重新打开页面后恢复状态 |
| 服务进程退出 | 持久化最后状态；重启后不得自动发送消息，显示“异常中断，等待人工继续” |
| 达到沟通列表额度 | 不再开始沟通候选人；全流程安全停止 |
| 达到推荐牛人额度 | 完成一次沟通列表回查后结束全流程 |

所有失败必须显示实际阶段和可操作原因，不能只显示“执行失败”或持续显示“轮询中”。

## 14. 活动日志

活动日志需要记录业务事件，不把普通状态轮询重复写成主要日志。至少记录：

1. 全流程启动及锁定岗位；
2. 沟通列表同步开始、成功、失败及人数；
3. 沟通列表立即待处理人数；
4. 候选人状态发生真实推进；
5. 推荐批次开始；
6. 推荐候选人成功联系、硬筛跳过或重复跳过；
7. 推荐批次达到 20 人或提前结束；
8. 返回沟通列表；
9. 暂停、继续、停止、额度耗尽和时间结束；
10. 全流程完成或失败。

连续轮询但状态没有变化时，不新增重复活动记录。页面可以显示最后检查时间，但不能
用大量“轮询”日志掩盖没有业务推进的问题。

## 15. 验收标准

### 15.1 功能验收

1. 自动化控制区出现“开始全流程自动化”按钮，原有按钮仍然存在。
2. 未选择岗位时不能启动。
3. 点击后自动同步当前岗位沟通列表，不要求用户提前手动同步。
4. 有立即待处理候选人时，必须先处理沟通列表，不能先操作推荐牛人。
5. 只有沟通列表没有立即待处理候选人时才进入推荐牛人。
6. 推荐牛人成功联系满 20 人后立即返回沟通列表。
7. 推荐牛人不足 20 人时，处理完当前可用候选人后返回沟通列表。
8. 推荐牛人产生的新会话能够在沟通列表阶段继续处理。
9. 推荐牛人回复后不会被再次当成首次对话，也不会重复提问。
10. 等待回复和等待附件的候选人不阻塞推荐牛人阶段。
11. 已回复专业问题的候选人优先得到评估，不重复发送专业问题。
12. 已分享简历的候选人优先进入简历确认、下载和分析动作。
13. 沟通列表和推荐牛人分别使用自己的每日额度。
14. 到达结束时间后完成当前步骤并停止，不开始下一位候选人。
15. 暂停、继续和停止对整个全流程生效。
16. 页面刷新后能够恢复当前阶段、批次人数和停止原因。
17. 全流程运行时不能启动两个独立自动化，反之亦然。

### 15.2 稳定性验收

1. 不允许两个来源并发点击 BOSS 页面。
2. 候选人列表变化时必须使用 `friend_id` 校验，不按旧索引误点。
3. 相同消息版本不能重复调用 AI 或重复发送回复。
4. 服务中断后不能自动恢复发送，必须等待人工继续。
5. 后台失败后页面在一个轮询周期内展示失败阶段和原因。
6. 没有业务状态变化时不得持续生成重复轮询日志。

### 15.3 自动化测试

至少覆盖以下测试场景：

1. 启动时先同步沟通列表；
2. 有立即待处理候选人时不启动推荐牛人；
3. 沟通列表无立即任务时启动推荐牛人；
4. 推荐成功联系第 20 人后切回沟通列表；
5. 推荐不足 20 人时提前切回沟通列表；
6. 返回沟通列表后优先处理新回复；
7. 等待回复和等待附件不阻塞阶段切换；
8. 两个来源分别达到额度时的处理；
9. 时间结束时完成当前步骤后停止；
10. 暂停、继续和停止；
11. 页面刷新后的状态恢复；
12. 独立自动化与全流程之间的互斥；
13. 沟通列表同步失败时不进入推荐牛人；
14. 推荐牛人失败时不丢失当前批次进度；
15. 同一候选人从推荐牛人转入沟通列表后不重复发送问题。

## 16. 已确认决策

1. 沟通列表没有立即待处理候选人时切换到推荐牛人，等待回复和等待附件不阻塞。
2. 推荐牛人每成功联系 20 人后返回沟通列表检查。
3. 推荐牛人产生的候选人后续统一在沟通列表处理。
4. 沟通列表始终拥有最高优先级。
5. 沟通列表和推荐牛人分别使用各自的每日额度。
6. 点击全流程按钮后自动先同步当前岗位沟通列表。
7. 到达结束时间后完成当前候选人的当前步骤，不开始下一位候选人。
8. 原有两个独立自动化按钮继续保留。
9. 全流程采用后台串行调度器，不依赖前端页面持续打开。
